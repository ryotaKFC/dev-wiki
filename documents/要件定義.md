# 個人用ナレッジWiki 要件定義

## 文書情報

- ステータス: 初版確定
- 確定日: 2026-10-28
- 想定利用者: 現在および将来の自分

## 目的

Codexとの会話で学んだ内容を、そのセッション限りで終わらせずに残す。
残した記事を後から検索して読み返し、自分の理解として定着させる。

単なる会話ログではなく、後から単独で読んでも理解できる個人用Wikiを作る。

## 対象とする知識

- ソフトウェア開発の概念や技術
- ライブラリやフレームワークの仕様と使い方
- Figma、Postmanなどのアプリや開発ツールの使い方
- その他、後から読み返したい知識や手順

## MVPの完成条件

以下を一連で実行できたら初期版を完成とする。

1. Codexとの会話で「Wikiに保存して」と指示する。
2. Codexが内容をテーマごとの日本語記事へ整理する。
3. Markdown、画像、出典、メタデータ、Wikiリンク、図解を検証する。
4. 専用ブランチへコミットし、GitHubでPRを作成する。
5. 元のCodexセッションが記事内容とPRのURLを返す。
6. GitHub上のCIとCodexレビューを通過したPRが自動マージされる。
7. Cloudflare Workersへ自動デプロイされる。
8. スマートフォンのChromeから記事を全文検索し、本文、目次、リンク、バックリンクを読める。

英語版、タグ、ダークモードなどの中優先度機能はMVP完成条件に含めない。

## 優先度: 高

### 記事の作成と更新

- ユーザーの明示的な保存指示を起点に、Codexが会話をWiki記事へ整理する。
- 新規記事は事前確認なしで保存し、完了後に記事タイトル、保存先、記事内容、PRのURLを返す。
- 1記事では1テーマだけを扱う。1回の会話に複数テーマがあれば複数記事へ分割する。
- 本文の構成は固定せず、題材に必要な見出しをCodexが選ぶ。
- 保存前に同一・類似テーマの記事を検索する。
- 既存記事がある場合は自動更新せず、変更案と変更箇所を提示してユーザーの判断を待つ。
- 既存記事は、ユーザーが変更案を承認した場合だけ更新する。
- 記事の削除・統合は、参照元とリンク切れの影響を提示し、ユーザーが承認した場合だけ実行する。
- 記事を統合した場合は、Wikiリンクを統合先へ更新し、旧URLから統合先へリダイレクトする。

### 記事データ

- Markdownを記事の正本とする。
- 各記事は専用フォルダを持ち、日本語本文を `ja.md`、画像を同じフォルダへ保存する。
- 画像を含む記事データはGitで履歴管理する。
- 固定メタデータとして `title`、`summary`、`slug`、`createdAt`、`updatedAt`、`verifiedAt`、検証状態を持つ。
- 対象バージョンが存在する記事は、対象バージョンも記録する。
- slugとフォルダ名は英語のケバブケースで一致させる。
- slugはタイトルを変更しても原則変更しない。
- 日本語記事のURLは `/articles/{slug}/` とする。

### 情報の信頼性

- 全記事に出典を記載する。
- 技術仕様やAPIは、公式ドキュメントなどの一次情報を優先して確認する。
- 仕様、数値、バージョン依存情報などの重要な主張には、本文中に番号付きの出典参照を付ける。
- 本文中の出典番号と、記事末尾の出典一覧を対応させる。
- 信頼できる出典を確認できなくても保存は可能とする。
- 未検証記事は検証状態を明示し、記事冒頭に信頼性を保証できない旨の警告を表示する。
- 未検証記事には `noindex` を設定する。
- 記事上部に最終検証日と対象バージョンを表示する。

### 記事の表示

- AstroでMarkdownを読みやすいHTMLとして表示する。
- 記事タイトルだけを `h1` とし、本文は `h2` 以下で構成する。
- `h2` と `h3` から目次を自動生成する。`h4` 以下は目次へ表示しない。
- デスクトップでは目次を本文横へ追従表示する。
- スマートフォンでは目次を記事上部へ折りたたんで表示する。
- コードブロックへ言語名、シンタックスハイライト、コピーボタンを表示する。
- 長いコードは折り返さず横スクロールで表示する。
- コピーの成否をユーザーへ通知する。
- Mermaidからフロー図やシーケンス図を表示できる。
- 構造、依存関係、3段階以上の処理、時系列を文章だけで理解しにくい記事には、Codexが適切な図を追加する。
- Mermaid図には説明と代替情報を付け、スマートフォンでも拡大またはスクロールできるようにする。
- アプリの操作手順には、理解に必要なスクリーンショットを含める。
- 画像には代替テキストを設定し、画面幅に合わせて表示する。
- スクリーンショットを用意できない場合は、必要な画面と状態が分かるプレースホルダーを残す。

### 記事間リンク

- `[[記事名]]` 形式で別の記事へリンクできる。
- Wikiリンクは記事タイトルからslugへ解決する。
- 記事を参照している記事の一覧を、バックリンクとして自動表示する。
- PRでWikiリンク切れを検出する。

### トップページと検索

- トップページには、大きな検索欄と最近更新した記事一覧を表示する。
- 最近更新した記事は更新日の新しい順とし、タイトル、概要、更新日を表示する。
- デスクトップでは全ページ共通ヘッダーに検索欄を表示する。
- スマートフォンでは全ページ共通の検索ボタンから検索UIを開く。
- Enterキーまたは検索ボタンで検索し、検索結果ページへ移動する。
- 空文字と空白だけの検索は実行しない。
- タイトル、概要、本文を全文検索できる。
- 日本語と英語の混在、大文字小文字を区別しない英字検索、部分一致に対応する。
- タイトル、概要、本文の順に一致の重みを高くする。
- 検索結果はGoogle検索風の縦一覧とし、記事タイトル、記事パス、本文抜粋を表示する。
- 本文抜粋では検索語を強調する。
- 0件の場合は検索条件の見直しと最近更新した記事を表示する。
- ビルド時に検索インデックスを生成し、ブラウザ側で検索する。
- 外部検索サービスを使わず、1,000記事程度まで扱えることを目標にする。

### UIとレスポンシブ対応

- WikipediaとMDNの中間のような、装飾を抑えたドキュメントUIにする。
- 本文の可読性を最優先し、本文幅、行間、見出し階層、余白を調整する。
- 配色は白、黒、グレーを中心としたモノクロにする。
- リンクは色だけに依存せず、下線や明度差でも区別する。
- 赤、黄、緑などはエラー、警告、成功など意味のある状態だけに使う。
- グラデーションや装飾目的の多色表現を使わない。
- 不要なカード、バッジ、角丸コンテナ、装飾、アニメーションを追加しない。
- アイコンは意味や操作を補助する場合だけ使う。
- 大げさで曖昧なコピーを避け、短く具体的な日本語を使う。
- UI部品は、必要な場合に限りshadcn/uiのAstro対応構成を優先して使う。
- shadcn/uiの公式APIと標準的な構造を維持し、独自再実装を増やさない。
- 検索UIやダイアログなど、操作状態が必要な箇所だけReactとクライアントハイドレーションを使う。
- スマートフォンの画面幅でも、閲覧、検索、目次、コード、図を利用できる。
- すべての操作をキーボードで実行でき、フォーカス位置を視認できる。

### 公開とデプロイ

- Wikiは認証なしでインターネット上へ公開する。
- 秘密情報、認証情報、公開できない個人情報を記事へ保存しない。
- AstroとAstro Content Collectionsを使用する。
- Cloudflare Workersへ公開する。
- Codexが専用ブランチの作成、コミット、プッシュ、GitHub PR作成まで実行する。
- 記事を作成したCodexセッションは、ローカル検証、記事の確認、PR作成、PRのURL提示まで担当する。
- PR作成後のレビュー、修正、再検証、マージ、公開はGitHub上で完結し、元のCodexセッションを維持しない。
- マージ後にCloudflare Workersへ自動デプロイする。
- GitHubリポジトリとGit履歴をバックアップとし、別のバックアップ先は設けない。

### PRの品質ゲート

- メタデータ、Markdown形式、出典の存在、外部リンク、Wikiリンクを検証する。
- フォーマット、Lint、型チェック、テスト、本番ビルドを実行する。
- 秘密情報や認証情報の混入を検出する。
- GitHub Actions上の独立したCodexが、正確性、重複、読みやすさをレビューする。
- レビュー用Codexはファイルを変更せず、構造化した指摘と合否結果をPRへ投稿する。
- 指摘やCI失敗があれば、別のCodex修正ジョブが必要最小限の修正をPRブランチへ追加する。
- 修正ジョブは、対応した指摘、変更内容、検証結果をPRへ投稿する。
- 修正後はCIと新しいCodexレビューを再実行する。
- 自動修正と再検証は最大2回までとする。
- 2回で通過しなければマージせず、失敗内容と試した修正をPRへ残す。
- 仕様が曖昧、複数の妥当な選択肢がある、またはユーザー判断が必要な場合は、修正前に停止して質問する。
- 必須CIとCodexレビューの合格をブランチ保護のマージ条件にする。
- PR作成時にGitHubの自動マージを有効にし、条件を満たした時点でマージする。

## 優先度: 中

### タグ

- 記事の任意メタデータとしてタグを設定できる。
- タグから関連記事を探せる。
- トップページにタグ一覧を表示する。

### 英語学習

- 日本語版を正本として、Codexが英語版 `en.md` を自動生成する。
- 英語版の想定読者は、英語をほとんど理解できない自分とする。
- CEFR A1〜A2程度を目安に、短い文と基本的な語彙を使う。
- ライブラリ名やAPI名など、正確性に必要な技術用語は原語のまま使う。
- AIレビューで日本語版との意味の一致と英語の難易度を確認する。
- 日本語版の更新時は英語版も再生成する。
- 日本語版と英語版で画像、slug、検証日、対象バージョンを共有する。
- 英語版URLは `/en/articles/{slug}/` とし、Astroのルーティングで管理する。
- 日本語版と英語版は記事上部のリンクで切り替える。
- 初回表示は日本語とし、ブラウザ言語による自動リダイレクトは行わない。
- 検証済み英語版がある場合だけ言語切替を表示する。
- 英語版の生成やレビューが失敗しても、日本語版の公開は止めない。
- 公開できなかった英語版は別PRで追加できる。

### 検索と表示

- 検索語の入力中に記事候補を表示する。
- OSの設定に追従してダークモードを適用する。

### 情報の鮮度

- バージョン変化がある記事は、任意の再検証期限を設定できる。
- 期限を過ぎた記事には、情報が古い可能性がある旨を表示する。
- 期限を過ぎても、自動更新や自動非公開化は行わない。

### 非ブロッキング品質検査

- トップ、検索結果、記事ページをLighthouseのモバイル設定で計測する。
- 目標値はPerformance 90以上、Accessibility 95以上、Best Practices 95以上とする。
- 目標未達でもPRは止めず、結果をPRへ投稿する。
- 同じ問題のIssueがなければ改善Issueを作成し、既存Issueがあれば測定結果を追記する。

## 優先度: 低

- Codexとの全会話を指示なしで自動保存する。
- 記事から確認問題を生成する。
- 忘却曲線などに基づいて復習時期を通知する。
- Web UIから記事を作成・編集する。
- 検索語の誤字補正、類義語展開、「もしかして」を表示する。
- PWAとしてインストールする。
- オフラインで記事を閲覧・検索する。
- ライト・ダークテーマを手動で切り替え、選択状態を保存する。
- サイトマップ、OGP、構造化データなどでSEOを最適化する。
- LaTeX記法のインライン数式とブロック数式を表示する。
- 検索欄、トップへのリンク、最近更新した記事を含む専用404ページを用意する。

## 対象外

- アクセス解析と利用者追跡
- Cookieを使った行動計測
- ブラウザ上でのコード実行
- Notion、Obsidian、既存Markdownなどからの一括インポート
- Codexレビュー・修正用GitHub Actionsの共通実装
- Codexレビューで使う共通 `AGENTS.md` とプロンプトの管理
- 上記の共通設定を管理する別リポジトリの設計と運用

## 非機能要件

### 対応ブラウザ

- デスクトップとAndroidでは最新版Google Chromeを最優先にする。
- 最新版Safari、Firefox、Microsoft Edgeでも記事の閲覧と検索を利用できる。
- 最新版iOS Safariでも記事の閲覧と検索を利用できる。
- Internet Explorerと古いブラウザは対象外とする。

### 公開と検索エンジン

- 検証済み記事は検索エンジンのクロールを許可する。
- 検索エンジンからの流入は許可するが、初期版の主要目的にはしない。

## 主要な技術方針

- フレームワーク: Astro
- コンテンツ: Astro Content Collections、Markdown
- UI: Astroを基本とし、必要な箇所だけReactとshadcn/ui
- 図: Mermaid
- ホスティング: Cloudflare Workers
- ソース・履歴・バックアップ: GitHub
- 自動化: GitHub Actions、Codexレビュー、Codex修正、GitHub自動マージ
